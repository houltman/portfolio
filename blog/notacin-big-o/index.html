Notación Big O: guía de complejidad algorítmica

Nov 2, 2024
algoritmos computación

La notación Big O permite describir cómo crece el trabajo que realiza un algoritmo cuando aumenta el tamaño de su entrada. No predice por sí sola el tiempo exacto en segundos: sirve para razonar sobre escalabilidad y comparar soluciones bajo supuestos similares.

Qué significa la notación Big O en algoritmos

En análisis de algoritmos, O(f(n)) expresa un límite superior asintótico para el crecimiento de una función, donde n representa el tamaño de la entrada. Al describir el peor caso, Big O ofrece una cota que el algoritmo no supera en crecimiento, salvo constantes y para entradas suficientemente grandes.

Al simplificar la expresión, se suelen omitir constantes y términos de menor crecimiento. Por ejemplo, 3n² + 5n + 10 se expresa como O(n²). Esto ayuda a comparar tendencias cuando la entrada es grande, pero no significa que dos algoritmos con la misma notación vayan a tardar lo mismo en la práctica.

Las tasas de crecimiento permiten entender por qué una solución que funciona con pocos datos puede volverse impráctica a gran escala. Son categorías de análisis, no garantías de una duración concreta.

Cómo leer el crecimiento de una función

  • O(1): una operación de acceso puede ser constante; buscar un valor en una tabla hash es O(1) en promedio bajo supuestos habituales, pero puede ser O(n) en el peor caso.
  • O(log n): una búsqueda binaria descarta aproximadamente la mitad de los candidatos en cada iteración y requiere que los datos estén ordenados.
  • O(n): una pasada completa por n elementos requiere trabajo proporcional al tamaño de la lista.
  • O(n²): dos recorridos anidados sobre la misma entrada suelen comparar hasta n × n pares.

Ejemplos de código para entender Big O

Una sola pasada por la lista tiene O(n) de tiempo y O(1) de espacio adicional:

def contiene_valor(valores, objetivo):
    for valor in valores:
        if valor == objetivo:
            return True
    return False

En cambio, comparar cada par tiene O(n²) de tiempo. El siguiente ejemplo también usa O(1) de espacio adicional porque no crea una estructura que crezca con la entrada:

def contar_pares_iguales(valores):
    pares = 0
    for i in range(len(valores)):
        for j in range(i + 1, len(valores)):
            if valores[i] == valores[j]:
                pares += 1
    return pares

Tiempo y espacio: dos formas de medir complejidad

La complejidad temporal estima cómo crece el número de operaciones con la entrada. La complejidad espacial estima cuánta memoria adicional requiere el algoritmo. Conviene distinguir el espacio auxiliar de la memoria ocupada por la entrada original.

Por ejemplo, crear una copia completa de una lista de n elementos requiere O(n) de espacio adicional, mientras que recorrerla y conservar solo un contador requiere O(1). Una solución puede reducir tiempo a cambio de memoria; la elección depende de las restricciones del sistema.

Por qué Big O ayuda a comparar algoritmos

Big O ayuda a detectar cómo podría escalar una solución antes de someterla a cargas mayores. También permite comparar enfoques, identificar bucles o estructuras costosas y decidir dónde conviene medir y optimizar.

Sin embargo, la notación no reemplaza los benchmarks. Para entradas pequeñas, una solución con más pasos de preparación puede ser más lenta pese a tener una mejor complejidad asintótica. El lenguaje, el hardware, la distribución de los datos y las constantes también influyen.

Pasos para analizar complejidad algorítmica

  1. Define n: especifica qué representa el tamaño de entrada.
  2. Cuenta operaciones dominantes: céntrate en las que crecen con n.
  3. Analiza los bucles: recorridos consecutivos suelen sumar; los anidados pueden multiplicar.
  4. Considera llamadas recursivas: expresa cómo se divide el problema y cuántas veces se resuelve.
  5. Separa tiempo y espacio: incluye la memoria adicional y las estructuras creadas.
  6. Aclara el caso analizado: mejor caso, caso promedio o peor caso pueden diferir.
  7. Mide cuando importe: valida las hipótesis con datos representativos y pruebas de rendimiento.

Big O, Omega y Theta: diferencias básicas

Big O describe una cota superior asintótica; Omega (Ω) describe una cota inferior y Theta (Θ) una cota ajustada, cuando el crecimiento queda acotado por arriba y por abajo por la misma función. No son sinónimos de peor, mejor y caso promedio: esos casos describen qué entradas se analizan, mientras que O, Ω y Θ describen cotas del crecimiento.

Conclusión: usa Big O para evaluar escalabilidad

La notación Big O es una herramienta para razonar sobre el crecimiento del tiempo y la memoria, no un cronómetro ni una predicción exacta. Identifica el tamaño de la entrada, analiza las operaciones dominantes, aclara el caso que estás midiendo y valida el rendimiento con pruebas cuando sea relevante. Así podrás comparar algoritmos y elegir una solución adecuada para tus datos y restricciones.
