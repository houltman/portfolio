SEO técnico: guía práctica para que Google rastree, indexe y posicione tu web

Nov 9, 2026
seo seo-tecnico rendimiento

El SEO técnico es el conjunto de optimizaciones que permiten a los buscadores rastrear, renderizar e indexar tu sitio sin obstáculos. Puedes tener el mejor contenido, pero si Google no puede acceder a él, entenderlo o cargarlo rápido, no competirá por las primeras posiciones. En esta guía revisarás los puntos que más impacto tienen hoy, con ejemplos que puedes aplicar en cualquier proyecto web.

Qué es el SEO técnico y por qué importa hoy

El SEO técnico se ocupa de la infraestructura de tu sitio, no de lo que escribes. Un buen enfoque se apoya en tres capas:

  1. Rastreo: el buscador debe poder descubrir y acceder a tus URLs.
  2. Indexación: el buscador debe decidir que tu página merece estar en su índice.
  3. Experiencia y rendimiento: la página debe cargar rápido, ser estable y funcionar bien en móvil.

Además, los buscadores con IA y los resúmenes generativos dependen de la misma base: contenido accesible, bien estructurado y con señales claras de qué es cada página. Un sitio técnicamente sólido es más fácil de interpretar tanto para Google como para otros sistemas que consumen la web.

Cómo auditar el SEO técnico de tu sitio

Antes de optimizar, mide. Estas herramientas gratuitas cubren la mayor parte del trabajo:

  • Google Search Console: informes de indexación, rastreo, Core Web Vitals y problemas de datos estructurados.
  • PageSpeed Insights y Lighthouse: rendimiento con datos de laboratorio y de usuarios reales.
  • Inspección de URL (Search Console): muestra cómo Google ve y renderiza una página concreta.
  • Un rastreador como Screaming Frog: detecta enlaces rotos, redirecciones, títulos duplicados y páginas huérfanas.

Empieza por el informe de Indexación de páginas en Search Console: te dice qué URLs están indexadas, cuáles no y por qué.

Rastreo e indexación: lo primero que debes resolver

1. Configurar robots.txt sin bloquear lo importante

El archivo robots.txt indica qué rutas pueden rastrear los bots. Un error común es bloquear carpetas de CSS o JavaScript que Google necesita para renderizar la página:

# public/robots.txt
User-agent: *
Disallow: /admin/
Disallow: /api/

Sitemap: https://tudominio.com/sitemap-index.xml

robots.txt controla el rastreo, no la indexación. Para evitar que una página aparezca en resultados, usa la etiqueta noindex y no la bloquees en robots.txt, porque Google no podría leer esa instrucción.

2. Generar un sitemap XML actualizado

El sitemap ayuda a descubrir tus URLs canónicas. Debe incluir solo páginas que quieras indexar: sin redirecciones, sin errores 404 y sin noindex. Si usas Astro, el paquete oficial lo genera automáticamente:

npx astro add sitemap

// astro.config.mjs
import { defineConfig } from 'astro/config';
import sitemap from '@astrojs/sitemap';

export default defineConfig({
    site: 'https://tudominio.com',
    integrations: [sitemap()],
});

Después, envía la URL del sitemap desde Search Console.

3. Evitar contenido duplicado con canonicals

Cuando una misma página es accesible desde varias URLs (parámetros, www, barra final), indica cuál es la versión preferida:

<link rel="canonical" href="https://tudominio.com/blog/seo-tecnico-posicionar-web/" />

Cada página debe tener un canonical que apunte a sí misma o a su versión principal. Mantén además una sola versión del dominio (con o sin www) y fuerza HTTPS con redirecciones 301.

4. Cuidar la arquitectura y los enlaces internos

Una estructura plana y lógica ayuda al rastreo y reparte autoridad entre tus páginas:

  • Cualquier página importante debería estar a pocos clics desde la home.
  • Usa enlaces <a href> reales; los enlaces que dependen solo de eventos JavaScript pueden no ser rastreados.
  • Usa anclas descriptivas (“guía de Core Web Vitals” en lugar de “haz clic aquí”).
  • Revisa páginas huérfanas: URLs que ningún otro enlace interno apunta.

Core Web Vitals: rendimiento que Google mide

Core Web Vitals son métricas de experiencia real de usuario. Se evalúan en el percentil 75 de las visitas:

MétricaQué mideObjetivo “bueno”
LCP (Largest Contentful Paint)Velocidad de carga del contenido principal2,5 s o menos
INP (Interaction to Next Paint)Capacidad de respuesta a las interacciones200 ms o menos
CLS (Cumulative Layout Shift)Estabilidad visual0,1 o menos

INP reemplazó a FID como métrica de interactividad, así que si tu optimización seguía basándose en FID, conviene actualizarla.

Mejorar el LCP

El elemento más grande suele ser una imagen hero. Opimízala y prioriza su carga:

<img
    src="/images/hero.avif"
    alt="Descripción clara de la imagen"
    width="1200"
    height="630"
    fetchpriority="high"
/>
  • Usa formatos modernos como AVIF o WebP.
  • No cargues con loading="lazy" la imagen principal visible al inicio.
  • Reduce el tiempo de respuesta del servidor (TTFB) con caché y CDN.

Mejorar el CLS

Reserva siempre espacio para imágenes, anuncios y embeds definiendo width y height (o aspect-ratio en CSS). Carga las fuentes con font-display: swap y precarga la fuente principal para evitar saltos de texto.

Mejorar el INP

  • Divide las tareas largas de JavaScript y difiere lo que no sea crítico.
  • Elimina scripts de terceros que no aporten valor.
  • Carga componentes interactivos solo cuando se necesiten (hidratación parcial o carga diferida).

Renderizado y JavaScript: que Google vea tu contenido

Google puede renderizar JavaScript, pero hacerlo es más costoso y puede retrasar la indexación. Para contenido que debe posicionar:

  • Prefiere SSG (generación estática) o SSR para que el HTML llegue con el contenido ya incluido.
  • Evita que títulos, textos o enlaces importantes dependan de una llamada a API tras la carga.
  • Comprueba el resultado con la Inspección de URL y revisa el HTML renderizado.

Si tu proyecto es una SPA pura, el SEO es posible pero exige más cuidado. Para sitios de contenido, blogs y portafolios, el renderizado en servidor o estático suele ser la opción más simple y estable.

Datos estructurados: ayuda a Google a entender tu contenido

Los datos estructurados en formato JSON-LD describen explícitamente qué es la página. Para un artículo de blog:

<script type="application/ld+json">
{
    "@context": "https://schema.org",
    "@type": "BlogPosting",
    "headline": "SEO técnico: guía práctica para posicionar tu web",
    "datePublished": "2026-11-09",
    "dateModified": "2026-11-09",
    "image": "https://tudominio.com/portfolio/images/blog/seo-tecnico.jpg",
    "author": {
        "@type": "Person",
        "name": "Gabriel Houltman"
    }
}
</script>

Valídalo con la Prueba de resultados enriquecidos o con el validador de Schema.org. Ten en cuenta que Google ha reducido los resultados enriquecidos disponibles para algunos tipos (por ejemplo, FAQ y HowTo), así que implementa schema para describir bien tu contenido, no solo para buscar un estilo visual en el resultado.

Etiquetas on-page que sí influyen

Aunque pertenecen a la optimización de página, son parte de una base técnica correcta:

  • <title> único por página, con la palabra clave principal y una longitud razonable (alrededor de 50 a 60 caracteres).
  • Meta description persuasiva (unos 150 a 160 caracteres). No es un factor directo de ranking, pero mejora el CTR.
  • Un solo <h1> y jerarquía lógica de <h2> y <h3>.
  • Atributo alt descriptivo en las imágenes.
  • URLs cortas y legibles, en minúsculas y con guiones.
  • Atributo lang en la etiqueta <html> y, si tienes varios idiomas, etiquetas hreflang.
<html lang="es">
<head>
    <title>SEO técnico: guía práctica para posicionar tu web</title>
    <meta name="description" content="Aprende SEO técnico paso a paso: rastreo, indexación, Core Web Vitals y datos estructurados." />
    <meta name="viewport" content="width=device-width, initial-scale=1" />
</head>

Móvil, seguridad y errores de servidor

  • Mobile-first: Google indexa principalmente la versión móvil. Asegúrate de que el contenido, los enlaces y los datos estructurados sean los mismos en móvil y escritorio.
  • HTTPS en todo el sitio, sin contenido mixto y con certificado vigente.
  • Códigos de estado correctos: 200 para páginas válidas, 301 para movimientos permanentes, 404 o 410 para contenido eliminado. Evita las cadenas de redirecciones.
  • Páginas 404 útiles, con enlaces a secciones principales.

Lista de comprobación de SEO técnico

  1. Todas las URLs importantes devuelven 200 y están en el sitemap.
  2. robots.txt no bloquea recursos ni páginas que deban posicionar.
  3. Cada página tiene un canonical correcto, un title único y una meta description.
  4. Core Web Vitals en verde en Search Console (datos reales, no solo de laboratorio).
  5. El contenido principal está en el HTML renderizado.
  6. Datos estructurados válidos y coherentes con el contenido visible.
  7. Sin enlaces rotos, cadenas de redirecciones ni páginas huérfanas.
  8. Versión móvil equivalente a la de escritorio.

Conclusión: prioriza el SEO técnico por impacto

El SEO técnico no sustituye a un buen contenido, pero lo habilita: sin rastreo, indexación y rendimiento sólidos, el resto del trabajo pierde eficacia. Empieza por lo que bloquea (indexación y errores), sigue con la velocidad y la experiencia, y termina con mejoras como los datos estructurados. Audita con datos reales, corrige por orden de impacto y vuelve a medir: los resultados suelen tardar semanas en reflejarse, así que revisa Search Console de forma periódica.
