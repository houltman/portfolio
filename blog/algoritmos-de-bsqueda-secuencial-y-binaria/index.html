Búsqueda secuencial vs. binaria: diferencias y ejemplos

Oct 25, 2024
algoritmos programación búsqueda

La búsqueda secuencial revisa los elementos uno por uno y funciona aunque la lista no esté ordenada. La búsqueda binaria descarta la mitad de los elementos en cada paso, pero solo es correcta si los datos están ordenados. Por eso, la mejor opción depende del tamaño, el orden y el uso que vayas a dar a la colección.

En esta guía verás cómo funciona cada algoritmo, su complejidad, ejemplos en Python y los criterios prácticos para elegir entre ambos.

Cómo funciona la búsqueda secuencial paso a paso

La búsqueda secuencial, también llamada búsqueda lineal, recorre una colección desde el principio y compara cada elemento con el valor buscado. Se detiene al encontrar una coincidencia o cuando ya no quedan elementos.

Su tiempo de ejecución es O(n) en el peor caso: si el elemento no existe o está al final, se revisan los n elementos. Si aparece al principio, termina antes; en promedio, una búsqueda exitosa en una lista sin ordenar puede revisar aproximadamente la mitad.

Ventajas de la búsqueda secuencial en listas

  • No requiere que los datos estén ordenados.
  • Es fácil de implementar y funciona bien con colecciones pequeñas.
  • Puede ser conveniente si solo necesitas buscar una vez y ordenar tendría un coste adicional.

Límites de la búsqueda secuencial en listas grandes

  • En el peor caso compara cada elemento, por lo que tarda más a medida que crece la colección.
  • Si haces muchas búsquedas en los mismos datos, repetir el recorrido puede ser menos eficiente que preparar una estructura adecuada.

Ejemplo de búsqueda secuencial en Python

La función devuelve el índice de la primera coincidencia o -1 si el valor no está presente:

def busqueda_secuencial(lista, objetivo):
    for indice, elemento in enumerate(lista):
        if elemento == objetivo:
            return indice
    return -1

numeros = [5, 2, 9, 1, 5, 6]
resultado = busqueda_secuencial(numeros, 5)
print(resultado)  # 0

Cómo funciona la búsqueda binaria en listas ordenadas

La búsqueda binaria compara el objetivo con el elemento del centro de una lista ordenada. Si el objetivo es menor, continúa en la mitad izquierda; si es mayor, en la derecha. En cada paso descarta aproximadamente la mitad del rango restante.

Su complejidad temporal es O(log n) y su espacio adicional es O(1) en esta implementación iterativa. Por ejemplo, buscar entre un millón de elementos ordenados requiere como máximo unas 20 comparaciones, frente a hasta un millón con una búsqueda secuencial.

Ventajas de la búsqueda binaria en listas grandes

  • Necesita muchas menos comparaciones cuando la colección es grande y ya está ordenada.
  • Es útil cuando realizarás muchas consultas sobre datos que cambian poco.
  • Puede localizar límites e inserciones ordenadas con variantes del algoritmo.

Requisitos y límites de la búsqueda binaria

  • La lista debe estar ordenada según el mismo criterio usado para comparar los elementos.
  • Ordenar tiene un coste: una ordenación general suele ser O(n log n). Si solo harás una búsqueda, puede que no compense.
  • En una lista con valores repetidos, una búsqueda binaria básica puede devolver cualquiera de las coincidencias. La función de abajo busca la primera.

Ejemplo de búsqueda binaria en Python

Esta versión mantiene el candidato encontrado y sigue buscando a la izquierda para devolver el primer índice coincidente:

def busqueda_binaria(lista, objetivo):
    bajo = 0
    alto = len(lista) - 1
    resultado = -1

    while bajo <= alto:
        medio = (bajo + alto) // 2
        if lista[medio] == objetivo:
            resultado = medio
            alto = medio - 1
        elif lista[medio] < objetivo:
            bajo = medio + 1
        else:
            alto = medio - 1
    return resultado

numeros_ordenados = [1, 2, 5, 5, 6, 9]
resultado = busqueda_binaria(numeros_ordenados, 5)
print(resultado)  # 2: índice de la primera aparición de 5

La complejidad indica cómo crece el trabajo con el tamaño de la entrada; no representa por sí sola el tiempo real. El coste de ordenar, la frecuencia de las consultas y la estructura de datos también influyen.

Cómo elegir el algoritmo de búsqueda adecuado

  • Elige búsqueda secuencial si la colección es pequeña, está desordenada o solo harás unas pocas consultas.
  • Elige búsqueda binaria si los datos ya están ordenados y necesitas buscar muchas veces.
  • Considera el coste total si tendrías que ordenar primero o mantener el orden después de cada cambio.
  • Usa herramientas estándar cuando encajen: en Python, el módulo bisect ofrece operaciones de búsqueda de límites en listas ordenadas.

Errores frecuentes al implementar una búsqueda

  • Aplicar búsqueda binaria a una lista desordenada: puede producir un resultado incorrecto sin avisar.
  • Actualizar mal los límites del rango: puede omitir elementos o dejar el bucle ejecutándose indefinidamente.
  • No decidir qué hacer con duplicados: documenta si quieres cualquier coincidencia o la primera.
  • Comparar algoritmos sin considerar el ordenamiento, las consultas repetidas y el coste de acceso a los datos.

Conclusión: elige según tus datos y necesidades

La búsqueda secuencial ofrece simplicidad y no exige ordenar; la binaria reduce las comparaciones, pero requiere datos ordenados. Para decidir, considera el tamaño de la colección, cuántas consultas harás y cuánto cuesta mantener los datos ordenados. Elegir con esos factores en mente permite mejorar el rendimiento sin añadir complejidad innecesaria.
